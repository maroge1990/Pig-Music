# Household security assumptions and review

Pig Music remains private to the household tailnet. HTTPS encrypts traffic; app accounts additionally prevent another tailnet device from browsing or editing a member's private library, playlists, favourites, requests and listening history. The administrator can manage the server and its files and is consequently trusted with all server data. This is not protection against a compromised administrator, NAS, Mac or Unraid host.

Passwords use Argon2id. Opaque session tokens are stored as hashes, browser cookies are Secure/HttpOnly/SameSite=Strict, and browser writes require a same-origin check and the Pig request header. Device credentials use Bearer authentication. Revocation, disabling a member and membership removal are checked again on media access, including signed URLs and Range requests. The last administrator cannot be disabled. Password reset is available through the existing interactive administrator CLI.

Plex tokens are encrypted with AES-GCM, with each user's identity bound to the ciphertext. The encryption key derives from the server authentication secret. Keep that secret with the database when restoring a backup; possession of both permits decryption. Appdata backups contain password hashes, private metadata and encrypted credentials, so restrict their access. No password, bearer token, member setup code or Plex token belongs in logs, screenshots or support exports. First-run installation proof is the deliberate exception: before any owner exists, startup prints a 128-bit installation code to the operator-only container console. It derives from the protected authentication secret with a separate HMAC domain, is never returned by HTTP, survives container restarts, and stops working permanently once any owner exists. Treat those startup logs as private and omit them from support exports. It is not an account password or a session token.

HTML uses a same-origin content policy, denies framing and disallows inline scripts. Inline styles remain permitted for layout and progress indicators. HTTPS responses advertise HSTS. JSON bodies are limited to 1 MB before parsing, including chunked requests; Apple XML imports retain their separate 20 MB bound. Validation errors omit submitted values. Setup codes expire and are one-use; failed sign-ins are rate limited and recorded. Only the administrator sees household security activity.

Manual review covered the account and shared-file diff: route classification/default deny, owner-only administration, private playlist ownership, no filesystem paths in member DTOs, membership and session checks on playback, setup-code replay/expiry, token hashing and redaction, encrypted Plex isolation, shared-file removal fingerprints and coordination, pending acquisition claim invalidation and migration rollback. Tests exercise these boundaries. Dependency checks on 7 October 2026 reported no known advisories in the locked Python dependencies or the frontend dependency tree; CI repeats the runtime checks before publishing an image.

Remaining acceptance requires real devices: account sign-in over private HTTPS on cellular, session revocation during playback, and VoiceOver/text-size journeys. Watch installation and headphone playback remain the separate feasibility gate. Local fixtures and simulator checks do not establish those results.

## First-run administrator setup

An unconfigured WebUI displays Welcome to Pig Music with installation-code help and name/username/password/confirmation fields. Status exposes only whether an owner exists and requires HTTPS. Creating the first owner also requires HTTPS, the Pig request header, same-origin protection, the installation code and existing password validation. Failed proof attempts use the persistent authentication rate limiter. Transactional first-owner creation permits only one owner under concurrent claims; disabling or clearing an owner's password never reopens registration. Existing owner attribution remains idempotent. Successful setup creates a secure web session. The interactive CLI remains a recovery/advanced alternative, not the normal fresh-install workflow.
