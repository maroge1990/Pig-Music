# Artist portraits and web playback

Added 5 October 2026. Saved music has a persistent browser player with album queues, play/pause, seeking, next/previous, mute, and browser Media Session controls where supported. Playback resolves saved IDs server-side against either the read-only NAS mount or appdata's acquired library. Paths cannot escape their own root. Native HTTP byte ranges support seeking; playback never retags, renames or copies the NAS library. MP3, AAC/M4A, FLAC, Ogg/Opus and WAV are served in their existing format. Target iPhone browser playback still needs household testing; there is no transcoding or Watch offline support yet.

Portraits are independent of album covers. Fanart receives a MusicBrainz artist ID with an API key in a private request header. Saved artists without an ID use a unique exact-name MusicBrainz lookup only when Fanart is configured; ambiguous names do not receive inferred IDs. The public ArtistGrid CSV provides a no-key fallback, matched locally with filename collisions rejected. Remaining artists retain representative album artwork. Cached images are bounded, decoded, resized and re-encoded into JPEGs. Provider failures fall back without blocking library metadata or downloads. ArtistGrid provides photos for only five of the existing 27 artist entries, so Fanart is needed for broader coverage.

Create a free Fanart account and a **Project API Key** for Pig Music at [Get an API key](https://fanart.tv/get-an-api-key/), then enter it in System → Artwork & playback. Paid VIP access is not required. Keys remain in the server's private `data/media-settings.json`, created with mode 0600 on Linux, and are never returned by settings responses. A blank input preserves the existing key. Backups containing this file must remain private. See [current API documentation](https://api.fanart.tv/).

Experimental remote playback is independent of downloading and can be disabled in Settings. It resolves a server-trusted catalogue release/song against the Monochrome Tracks endpoint, requiring matching artist, full versioned title, album, duration and ISRC when supplied. Ambiguous candidates and non-audio responses are rejected. The provider stream opens directly in the browser; no remote music file is saved by Pig Music. Its codec and exact mastering are not verified. The public endpoint timed out from both Windows and Unraid on 5 October; no live remote playback has been confirmed. The adapter and unavailable-source message are implemented, with successful and failing provider responses covered by mocked tests. This feature must remain experimental until an actual stream works.

Validation: 45 backend tests passed, including byte-range responses, separate library roots, traversal rejection, API-key redaction, bounded persistent portraits, filename collisions and edition-aware remote matching. Production frontend build passed. Live verification results are recorded below after deployment.

# Shazam recommendation

Start with an iPhone Shortcut receiving Shazam's shared song link, sending it through existing Tailscale access into a Pig Music discovery inbox. An optional second entry point can use Shortcuts' built-in Shazam action to identify and send in one workflow. Review/select a recording and add the **song**, without implicitly requesting the whole album or artist. Keep discoveries separate from the download queue until accepted. This avoids making Apple Music a permanent dependency and suits identifying songs while out. The shortcut and inbox are proposed next work, not implemented in this milestone.

Official sources: [Shazam sharing](https://support.apple.com/en-me/guide/shazam/deva91f77c6a/web), [recognition in Shortcuts](https://support.apple.com/en-az/guide/shazam/deve5143aaf5/web). A share shortcut needs no Shazam API key. Later, the native iOS app can add a Listen button using [ShazamKit](https://developer.apple.com/shazamkit/), with the ShazamKit service enabled for its app identifier and microphone permission. Its recognition returns recording metadata for the same inbox and matching pipeline.

Automatic access to the entire existing Shazam history is not provided by SHLibrary: Apple explicitly restricts reading/deletion to discoveries added by the calling app. A playlist/export import or explicit sharing is required for existing Shazam-app discoveries. See [Apple WWDC23, SHLibrary](https://developer.apple.com/videos/play/wwdc2023/10051/). Linked Apple Music/Spotify playlists can provide an interim migration route, but should not underpin the long-term integration given the planned Apple Music retirement.
