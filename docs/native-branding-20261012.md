# Native PigMusic branding

12 October 2026 · Pig family **1.7.0** · app **0.2.0 (3)**.

The source is the official Pig-Branding repository's `tokens/brand-tokens.json`, `docs/pig-family-brand-guide.md`, `docs/integration.md` and `assets/products/pig-music`. The guide is design reference for this integration; it does not authorize app renaming, deployment or changes to the branding repository. Existing display names and bundle identifiers are retained.

## Integration

- Phone and Watch vendor the approved vector mark, outlined horizontal light/dark wordmarks, monochrome product glyphs and dynamic semantic colours. No font binary, redraw, aspect-ratio change, new palette or album-art recolouring is introduced.
- Shared `PigBrand` resolves canvas, foreground and rose actions for each appearance. The quiet corner bloom uses the prescribed 16% light / 13% dark rose, radius 62% of the canvas diagonal, mirrors for right-to-left and disappears with Reduce Transparency. Content stays on opaque surfaces; the current phone song uses a 14% rose overlay on the surface plus a leading marker and accessible current-song value. Native picker/toggle selection semantics remain intact.
- Phone's floating mini-player and Watch's transport group use system glass on iOS/watchOS 26+, with solid surface/boundary fallback on older systems or Reduce Transparency. Increased contrast adds the control boundary. Primary actions use rose glass buttons with the prescribed on-accent label colour; reading content, artwork and branding are outside glass. System bars and scroll-edge treatment remain native.
- Phone now-playing respects the chosen appearance rather than forcing a dark screen. Artwork remains prominent and receives system concentric corners where available, with a 16-point fallback. Interface type remains Dynamic Type; Watch playback times/storage figures use rounded tabular digits.
- The iOS Icon Composer document uses exact approved body and face vectors, halo backgrounds and dedicated mono variants. Face stays above body, with halo behind. Default/dark/mono groups are present in the compiled asset catalog; mono supplies tinted and clear system appearances. Approved square catalogs remain available as fallbacks. The Watch uses the approved dark square export with the system's circular mask; it does not use an independently recoloured or pre-masked illustration.
- Phone's static launch storyboard uses the canvas and approved halo/pig with no text or motion. Both apps show the matching pig composition during restoration, with the prescribed four-second alternating bloom. Reduce Motion keeps the halo static; Reduce Transparency removes decorative glow. Restoration ends the splash immediately, with no minimum delay.

Assets and canonical tokens are copied into Pig Music, so opening Xcode or building CI does not depend on an adjacent branding checkout. `scripts/sync_native_brand.py --source /path/to/Pig-Branding` refreshes version 1.7.0 imports; a new version requires review. Run `python3 scripts/sync_native_brand.py --check` and `python3 scripts/generate_brand_tokens.py --check` to verify provenance and generated roles. `docs/native-brand-assets.json` records source-relative paths and SHA-256 checksums. The Icon Composer layout document is maintained separately from asset refreshes. Generated web palette values are unchanged; only their source version comment changes.

## Xcode project and acceptance

The current shared project is **`swift/PigMusic.xcodeproj`** inside **`pig-music-fixes`**, with schemes **PigMusic** and **PigMusicWatch**. PigMusic embeds the Watch app. `scripts/generate_native_project.py` regenerates it, including the icon and launch storyboard, with no personal signing settings.

Local verification: phone/embedded Watch Debug simulator builds pass; standalone Watch Release simulator build passes; unsigned iPhone/embedded Watch hardware build passes. Asset provenance verifies all 73 imported files; generated token checks, deterministic project regeneration, Swift formatting and diff checks pass. The compiled phone catalog contains default/dark/mono body, face and halo groups. Native rendered-screen checks did not complete: disposable simulator boot/install operations stalled, and both task-owned QA simulators were removed. No install was performed on the preserved default simulator. CI runs are checked after publishing. Final device review still covers Home Screen default/dark/tinted/clear appearances and masking, Watch circular icon/header/transport layout, large text/VoiceOver, increased contrast, Reduce Motion/Transparency and real headphone playback. Compilation does not substitute for those checks. The main phone/Watch functional acceptance checklist remains in [the build handoff](native-phone-watch-build-20261012.md).
