# M04 shared-file lifecycle — removal checkpoint

7 October 2026. Implemented in development; not deployed. The live service remains audit-followup-20261007-v1. M04 is not complete.

The personal API now provides removal preview, confirmation and caller-scoped undo for up to500 tracks. Preview names other holders only in the removal confirmation. The mutation checks current ownership, memberships, other pending request beneficiaries and file size/mtime against the confirmation before writing. Changed sharing returns409. Responses omit filesystem paths.

Caller memberships are removed together in one transaction. Files retained by another member or their active request remain intact. Final-member files use the existing mount/path/hash-checked recoverable trash system; playlist/favourite/history references do not keep files alive. Durable removal intent, exclusion, original memberships and claim cancellation commit before filesystem mutation. The caller is detached from shared pending requests so later publication cannot unexpectedly restore their membership. Undo is restricted to the caller for30 seconds; owner Recovery restores the original surviving accounts' memberships along with the file.

Membership addition, request attachment/publication/recovery, replacement cleanup, quality scheduling, scans, organisation and exports share a reentrant lifecycle lock. This currently serializes household mutations, including long scans, rather than using finer per-track locks. Read projections retain their separate locks. The order avoids taking the artwork lock while holding the library lock. A committed removal intent rejects additions even before disk recovery finishes. Multiple selected metadata identities pointing to one physical file require administrator review before mutation; no memberships or files change in that case.

Verification covers shared then final removal, partial albums, playlist-only references, other pending requests, stale confirmations, caller isolation, undo expiry, mount/file drift, interrupted recovery, add/remove races, cancelled publication, original safeguards and duplicate physical aliases. Full-suite/container evidence is recorded below after completion.

Remaining M04 work: per-user effective quality preferences and conflict resolution; owner-only Unassigned scan assignment; explicit rescan/organisation membership acceptance; device-copy invalidation integration when native copy storage exists; finer mutation coordination if household scans need concurrent writes. The authenticated confirmation/undo screens are part of M07. No deletion, account activation or filesystem mutation was exercised on the live NAS; tests use disposable music fixtures.
